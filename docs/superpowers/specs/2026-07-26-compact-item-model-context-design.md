# 精简题目模型上下文设计

## 目标

消除 `generate_item`、`revise_item` 和 `regenerate_item` 向模型发送完整
工作流状态的问题，同时保留断点恢复、审计记录和本地校验所需的完整状态。

成功标准：

- 题目模型请求不包含完整 `PSJTState`。
- 重写时仍能获得当前题目、版本、蓝图单元、题目规格、测量诊断、用户反馈和必要的去重资料。
- 题目标识、版本递增、情境类别和选项数量等现有校验继续生效。
- 完整测试通过，并用失败断点验证请求规模显著下降。

## 方案比较

### 方案 A：只提高超时

改动最小，但会继续重复发送约 236 万字符的请求。它不能解决上下文上限、
上游排队和费用问题，因此不采用。

### 方案 B：删除题目请求中的完整状态，传递白名单上下文

为题目模型构造一个独立、显式的精简 `state`，只包含本次生成或重写需要的
字段。工作流内部和断点文件仍保存完整状态。该方案边界清晰、风险可测试，
因此采用。

### 方案 C：全系统统一上下文裁剪框架

长期可扩展，但会同时影响路由、构念建模、审题和报告等多个模块，超出本次
故障范围，因此暂不采用。

## 数据设计

题目模型输入保留现有外层结构，但其中的 `state` 改为白名单对象：

- `current_item`
- `current_item_specification`
- `current_blueprint_cell`
- `test_specification`
- `active_psychometric_diagnostic`
- `user_feedback`

继续单独传递：

- `target_item_id`
- `target_blueprint_cell_id`
- `generation_context`
- `required_context_category`
- `validation_feedback`
- `previous_invalid_candidate`

`generation_context` 继续包含配额、最近题目特征和最相似题目特征。不得包含
`execution_history`、虚拟被试、完整题库、完整题目历史或完整统计记录。

## 数据流

完整 `PSJTState` 只在程序内部流动。执行题目动作时，程序从完整状态提取
白名单上下文，交给模型；模型返回单题候选；程序仍使用完整状态执行身份、
版本、蓝图和评分结构校验，然后把通过的候选合并回完整状态。

输出结构修复重试沿用同一份精简上下文，只额外加入校验反馈和上一次无效
候选，不重新加入完整状态。

## 错误处理

超时和有界重试策略保持不变。此次不通过提高超时掩盖问题。如果精简后仍然
超时，现有错误信息继续报告具体动作、题目 ID、单次超时和尝试次数。

## 测试

增加回归测试，拦截题目 Agent 的实际输入并确认：

1. `state` 不含 `execution_history`、虚拟被试和完整题库等字段。
2. 重写必需字段仍存在。
3. 输出校验修复重试仍使用精简上下文。
4. 使用现有失败断点计算输入规模，确认不再接近原来的约 236 万字符。
5. 运行完整测试套件，检查其他工作流行为未被改变。
